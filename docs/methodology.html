Methodology

Two explicitly separate stages, separately validated, plus the emission and format machinery. Pre-registration: GEMSDOE44-PREREG-1 (4-quadrant spatial block folds; fixed budget per arm; promotion rules fixed before the run — evidence/stage2_holdout.json records the rules alongside the results).

0. The metric, implemented and verified

Official distance-weighted Tversky index (published formulae), implemented in src/gems44/metric.py and test-verified line by line (tests/test_metric.py, 8 tests, all passing):

  • triangular kernel k(d) = max(1 − d/R, 0), R = 3 px (300 m at 100 m);
  • TPw = Σg∈G maxx: d≤R p(x)·k(d(x,g)); FPw = Σx: p>0 p(x)·[1 − maxg k(d(x,g))];
  • FNw = Σg [1 − maxx: d≤R p(x)·k(d(x,g))] = |G| − TPw (exact identity, used throughout);
  • DTI = TPw / (TPw + 0.2·FPw + 0.8·FNw + ε); worked example TP=3.00, FP=1.89, FN=2.00 → 0.60 reproduced;
  • full metric cross-checked against an independent brute-force O(|G||P|) implementation on a synthetic grid.

Convention flag (IR-44-METRIC-01): the lattice distance convention (Euclidean vs Manhattan) of the server-side implementation is not public — the reference-solution notebook only contains the training loss. We implement the published formulae with Euclidean pixel distance; for 0/1 dots inside a 3-px kernel the difference between conventions is small and bounded, and we disclose it rather than pretend it is zero.

1. Stage 1 — coarse favourability gate (the “worth searching” question)

2 km × 2 km superpixels (187×165 = 30,855). Per-superpixel features (11): p90 of geod_shearrate, geod_dilaterate, geod_2ndinv (kinematic activity); log-sum of deq+ieq (seismicity); p90 of cond_surf, tc (hydrothermal/radiometric proxies); p99−p1 range of iso_grav_anom; −median depth_to_base_surf (shallow base); log counts of relay-zone and endpoint-uncertainty stamps; log count of heat-flow wells ≥ 1500 mW/m².

A gradient-boosted classifier (positive superpixel = ≥ 3 catalogue pixels — a fault line crossing a 2 km block) is trained in each fold on the other three quadrants and evaluated in the held-out quadrant on two metrics that answer the coarse question only:

  • zone AUC — can favourability rank zones by known-fault content?
  • concentration ratio — fraction of the fold's catalogue pixels inside the top-q zones, divided by q (1.0 = no better than random; the gate must beat the baseline convincingly to earn its place).

The gate keeps the top-q superpixels (q selected by the pre-registered rule in evidence/gate_q_selection.json). Separately-validated disclosure (IR-44-PROXY-01): the only verifiable proxy for “worth searching” is the visible catalogue; this test is a necessary-condition check and cannot reward genuinely new faults. The Stage-1 numbers are therefore reported on their own and never collapsed into a single “system” number with Stage 2.

2. Stage 2 — fine-scale placement model (the “where the pixel is” question)

A gradient-boosted pixel classifier over 28 channels, trained on the catalogue proxy with spatial-block folds (positives = all catalogue pixels in the training quadrants; 5× random footprint negatives). Channels, grouped by hypothesis (hypotheses page):

Per fold, each of five arms emits 10,000 dots (same budget, 200 m exclusion radius, inside the held-out quadrant, under the same gate and the B=2 catalogue-flank mask applied to the candidate field before emission):

  • A0 random — the budget baseline;
  • A1 habitat-only — the Stage-1 favourability field as the placement score (the conflation the brief forbids, measured explicitly so its failure mode stays visible);
  • A2 single-field — |detrended-elevation slope| only (the classic scarp detector);
  • A3 H1-only — the multi-physics consensus alone (isolates its contribution);
  • A4 full model — the 28-channel model.

Each emission is scored with the official DTI against the held-out fold's catalogue. Promotion rule (fixed before the run): A4 > A0, A1, A2 in ≥ 3/4 folds and A4 > A3 in ≥ 2/4 folds and Stage-1 concentration ratio ≥ 1.3 in ≥ 3/4 folds. Results: holdout page.

3. Emission — the DTI-optimal shape

From the metric: TPw saturates at 1 per truth pixel (max rule), so a second dot on the same truth pixel is pure FP cost, and every off-target dot costs up to 0.2 while an exact hit costs 0. The optimal shape of a fixed dot budget is therefore well-separated 0/1 dots placed where the score field is highest — greedy best-first with a 200 m exclusion radius. Budget N is chosen by a pre-registered sweep (30k/35k/40k/45k, evidence/budget_sweep.json); the 200 m catalogue-flank removal is applied to the candidate field before emission (mass that can never earn round-1 credit — the hidden truth is off-catalogue by construction — is not wasted). This layout family is the same family the group's best files use (disclosed); the positions come entirely from this system's two stages, and the uniqueness check below quantifies the residual overlap with previously-scored files.

4. Format — why the portal rejected the old files, and the guarantees here

The DrivenData portal error “Predicted values must be in range [0, 1]” has two measured mechanisms (GEMSDOE32's analysis, which we re-audit byte-for-byte): (1) out-of-range values — the feature stack's nodata sentinel −3.4028234663852886e+38 passes through unchanged if a pipeline forgets to clean it; (2) an out-of-range nodata tag — a GeoTIFF whose nodata value is that sentinel (or NaN in a strict validator) is rejected even when the in-range cells are fine. Our writer (src/gems44/emit_submission.py) writes single-band float32, EPSG:32611, 100 m, 3730×3292, official geotransform, no nodata tag, every cell finite and in [0,1] — then re-opens the written file from disk and records a checks receipt (evidence/audit-*.json): 12,279,160 cells checked, not 3,061 sampled.

5. Mirror (live-anchored) truth model — and its honest limits

The hidden test set is, by construction, faults not in the visible catalogue, so no catalogue-based instrument can see it. The group's owner-report-derived inference (GEMSDOE25 H28): the hidden set is scattered around structure surfaces at σ ≈ 1.85 px. Our independent re-implementation scatters the catalogue with 2-D Gaussian noise (σ swept 1.5 / 1.85 / 2.5 px), scores candidate files against the scattered copies with the official metric over paired seeds, and reports mean ± se. This is a model — it is a statement about this generative description of the hidden set, not about the actual one. It is used to compare candidate files (ours vs incumbents) at equal footing, never as a score estimate.

6. Uniqueness — “not dominated by one stage's footprint alone”

Two checks, both reported in holdout page: (1) dominance — the emitted dots' distribution across Stage-1 favourability deciles (by construction all inside the gate; the decile histogram shows the mass is spread over the gate, not concentrated in one zone family); (2) uniqueness vs incumbents — pixel overlap of our dot set with four previously-scored dot sets (0.2778 / 0.2708 / 0.2600 / 0.2449 files, mirrored and hashed here), against the random-overlap expectation n₁·n₂/F for sets of those sizes inside the footprint.

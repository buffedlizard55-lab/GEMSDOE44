IR-44-BAND6-01 Band-6 semantics conflict between two of the group's own sites. GEMSDOE25 band_semantics.json measured Spearman 0.9999 between band 6 and the GeoDAWN radiometric total-counts product (K/Th/U correlations 0.886/0.913/0.717). GEMSDOE32's hypothesis page quotes the organizer band description as “tilt angle or total curvature — magnetic field derivative FOR EDGE DETECTION” and registered H61-3 (TDR zero-crossing on band 6) on that reading. GEMSDOE25 evidence/band_semantics.json (measurement) vs GEMSDOE32 hypotheses.html (quote). The official problem page shows both radiometric and magnetic products in the feature set, so both readings are textually plausible — which is exactly why the conflict matters. We follow the measurement (radiometric counts) — a measured Spearman 0.9999 against the source product outranks a quoted label. Consequence: G44-H5/H61-3-style transforms on band 6 are treated as radiometric, not magnetic. Flagged here for a reviewer with the original band spec sheet.
IR-44-PROXY-01 Catalogue-proxy ceiling. All blocked-holdout validation uses the visible catalogue as truth. The hidden set is off-catalogue by construction, so no local instrument can reward a genuinely new fault (same caveat as GEMSDOE32 IR-32-PROXY-01). competition problem description: “newly identified faults … not included in the existing USGS fault database … comprise the test dataset”. Stage-1 and Stage-2 numbers are reported per stage and explicitly labelled “proxy DTI vs catalogue”. The mirror model is a labelled model. No claim on this site reads as an organiser score.
IR-44-METRIC-01 Server-side distance convention not public. The official page states “distance to the nearest ground truth pixel … triangular kernel, 300 m support” without specifying the lattice distance (Euclidean/Manhattan/Chebyshev). The reference solution contains no DTI code. tests/test_metric.py verifies our implementation of the published formulae (Euclidean pixel distance) against a brute-force reference; the convention choice is documented in metric.py. Flagged, not papered over. For 0/1 dots with a 3-px kernel the convention difference is small and bounded; a submission scored under a different convention than ours would differ slightly, which is true of every participant.
IR-44-CIRC-01 Partial circularity of the relay/endpoint prior (G44-H3). The 290 gap links are derived from catalogue segment endpoints, so a holdout that uses the catalogue as truth partially rewards the prior by construction (measured lift: p99 relay lift ≈ 6×10⁶ — i.e., the catalogue sits on its own gaps). evidence/stage2_holdout.json channel diagnostics; lift computed in this session's channel diagnostics (raw p99 catalogue/field ratio). The channel is reported separately in the holdout so its effect is visible, the B=2 flank mask keeps emission off the mapped line, and the physical reading (relay ramps host unmapped faulting) is the one we want for the hidden set — the circularity inflates the proxy, it does not fake the mechanism. Disclosed.
IR-44-EGRESS-01 Sandbox egress is allow-listed (github.com, pypi.org, drivendata.org via reader; dropbox.com, usgs.gov, sciencebase.gov, docs.nlr.gov, nbmg.unr.edu, gdr.openei.org not reachable). Official data therefore enters via the group's sha256-pinned GitHub mirrors, each pin naming the official source URL; byte-for-byte verification is in evidence/verify_rasters.json. HTTP 000 probes recorded this session; GEMSDOE repo data/bridge/manifest.json (pins + official mirror URLs). Every file we use from a mirror carries its sha256 pin and its official URL on the sources page. Items needing direct egress (DEM tiles, MCRE vector, rules PDF bytes) are registered, not claimed: G44-R1/R2.
